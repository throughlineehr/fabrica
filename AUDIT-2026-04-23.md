# Fabrica Audit — 2026-04-23

Three concurrent audits: CQRS/agent completeness, architectural separation
of concerns, and WCAG 2.1 Level AA compliance of the new processor/signal
subsystem. Findings are consolidated into an ordered remediation roadmap
at the bottom. All net-new debt items have been copied into `DEBT.md`.

Scope: everything shipped this session — signal wiring (`src/signals/`),
switchboard UI (`src/components/room/`), processor page, checkbox
component — plus regression-check of the pre-existing surfaces those
interact with (App.jsx, SystemPage, ExplorerTree, SettingsPanel).

---

## Executive summary

| Concern | Grade | Top finding |
|---|---|---|
| CQRS | **D** | Entire processor subsystem bypasses the agent API. Three critical commands missing; ~11 direct-mutation paths in App.jsx & Switchboard. |
| Architecture | **B+** | One real violation (`wiring.js` hardcodes `room:` instead of using the `roomChannel()` helper). Two dead exports. `CLAUDE.md` references a file that no longer exists. Otherwise clean. |
| WCAG 2.1 AA | **C+** | VPAT claims ~95% but doesn't cover the new components. Five AA-blocking issues: row keyboard nav missing, modal focus trap incomplete, status announcements missing on processor ops, terminal dots below target-size, anchors misused as buttons in CableTerminal. |

The fixes are all tractable. No structural rework needed. Rough estimate:
**8–12 hours of focused work** to close everything to a state where a VPAT
refresh can honestly claim full AA.

## 1 — CQRS / agent API completeness

### Context

`COMPLIANCE-ROADMAP.md` §10 commits to "command pattern is the wire
protocol." The agent API at `src/agent/commands.js` is the single intended
surface for: AI agent control, future audit logging, future undo/redo,
future websocket sync. Every human-triggerable mutation should pass
through it — otherwise those downstream features go blind.

### Existing commands

**Model mutations** (full coverage):
`addManagement`, `addOperation`, `removeNode`, `renameNode`, `moveNode`,
`insertParent`, `spliceNode`, `detachNode`, `duplicateSubtree`,
`replaceModel`, `validate`.

**Navigation**: `overview`, `focus`, `detail`, `openSystem`, `back`.

**Queries**: `read`, `getState`, `getNode`, `listNodes`.

**Panels/Filters**: `openPanel`, `closePanel`, `setFilter` (system
visibility only).

### Missing / bypassed

#### Critical (data mutations agent cannot do but human can)

| Action | Location | Proposed command |
|---|---|---|
| Add processor to room | `App.jsx:109–122`, `Switchboard.jsx:184–187` | `addProcessor(nodeId, systemKey, defId, config?)` |
| Remove processor from room | `App.jsx:124–130`, `Switchboard.jsx:325–335` | `removeProcessor(nodeId, systemKey, instanceId)` |
| Update instance filters (types/tags/inputTerminals/outputTerminals) | `App.jsx:132–140`, `Switchboard.jsx:189–192, 282, 305, 312, 319` | `updateProcessorFilters(nodeId, systemKey, instanceId, patch)` |

Every one of these mutates App state through a plain React callback
(`onAddProcessor`, `onRemoveProcessor`, `onUpdateProcessor`) that
bypasses `createAgentAPI` entirely. The agent currently has no vocabulary
for the processor subsystem.

#### Important (gaps / violations)

| Action | Location | Proposed |
|---|---|---|
| Open processor detail page | `App.jsx:311–314`, `Switchboard:288–299` | `openProcessor(nodeId, systemKey, instanceId)` |
| Direct `setModel()` paths in App.jsx handlers (548, 554, 558, 562, 566, 627) | Bypass existing agent commands that already exist | Repoint TabSystem/HUD handlers to call `agentAPI.removeNode()` etc. instead of importing `removeNode` from `tree/` directly |
| Set language | `SettingsPanel.jsx:96` | `setLanguage(langCode)` |
| Toggle epilepsy / dyslexia / colorBlind | `SettingsPanel.jsx:116/121/124` | `toggleAccessibility(mode)` |
| Set font visibility scale | `SettingsPanel.jsx:118` | `setFontVisibility(0–1)` |

#### Minor (AI config)

`setAIProvider`, `setAIModel`, `setAIOllamaEndpoint`, `setAIKey`. These
are user preferences that would ideally be loggable for "who changed
what setting," but they're not model mutations.

### Remediation plan

**Phase 1 — processor commands (P0, ~2 hours)**

1. Add `addProcessor`, `removeProcessor`, `updateProcessorFilters`,
   `openProcessor`, `listProcessors(nodeId, systemKey)` to
   `src/agent/commands.js`. Each accepts the App-level update callbacks
   via `createAgentAPI({ processors: { add, remove, update, open, list } })`
   and delegates through them.
2. Rewire `App.jsx` to expose these callbacks via the agent runtime
   instead of passing them down as props directly.
3. Rewire `SystemPage` → `Switchboard` to invoke `agentAPI.*` instead of
   the current prop-callback chain. The Switchboard still needs a
   lightweight context (`useAgent()`) or it gets the agentAPI via prop.
4. Update `AGENT_DSL` with the new commands.
5. Extend `AgentPanel` natural-language handler if needed.

**Phase 2 — existing-handler rewiring (P1, ~1 hour)**

Lines in `App.jsx` (548, 554, 558, 562, 566, 627) import `removeNode`,
`moveNode`, etc. directly from `tree/index` and call them with
`setModel`. These mutations have agent commands (`agentAPI.removeNode`,
etc.) that do the same work plus the announce-and-return-result plumbing.
Switch to the agent versions.

**Phase 3 — settings commands (P2, ~1 hour)**

Add `setLanguage`, `toggleAccessibility`, `setFontVisibility`,
`setAIConfig` to the agent. Route `SettingsPanel` through them. This
completes the "everything is a command" invariant so audit logging
(Phase 4) has full coverage.

**Phase 4 — audit logging (deferred, not in this remediation)**

Once all mutations flow through `createAgentAPI`, add a simple
`commandLog.push({ timestamp, command, args, result })` wrapper. This is
table stakes for the SOC 2 / StateRAMP roadmap.

### Violations of the "commands are deterministic" invariant

For future websocket replay (`COMPLIANCE-ROADMAP.md §10.4`), commands
must be deterministic: given identical model + args, produce identical
result. Current `addProcessor` uses `crypto.randomUUID()` for
`instance.id` — fine for local but **non-replayable** over the wire.
When moving to websocket/server-authoritative: the server should
generate instance IDs and return them in the command result, not the
client.

Not a blocker now; flag for the websocket migration.

## 2 — Architectural separation of concerns

### Invariants

As documented in `SIGNALS.md` §1 and `CLAUDE.md`:

1. `signals/` is framework-free (no React imports except `BusContext.jsx`
   and `useSignalLog.js`).
2. `tree/` is 100% pure: immutable commands, no React, no bus, no I/O.
3. `bus.js` is the only transport seam — channel names live there too.
4. `components/` consume `signals/` and `tree/`, not vice versa.
5. Terminals drive both rendering and wiring from one definition.

### Findings

| # | Invariant | State | Evidence |
|---|---|---|---|
| 1 | `signals/` framework-free | ✅ | Grep confirms no React imports outside BusContext + useSignalLog. |
| 2 | `tree/` 100% pure | ✅ | All functions return new objects; zero side effects. |
| 3 | `bus.js` sole transport seam | ⚠️ **Violation** | `src/signals/wiring.js:23` hardcodes `` `room:${sourceRoomKey}` `` instead of calling the exported `roomChannel()` helper. Exact kind of drift the helper was supposed to prevent. |
| 4 | No upward layer dependencies | ✅ | Zero imports from `components/` in `signals/` or `tree/`. |
| 5 | Terminals drive rendering + wiring | ✅ | `topology.js:buildRoomTerminals` is the single source of truth. RoomShell consumes it; topology.js consumes it for subscription computation. |

### Dead / stale code

| Item | Location | Notes |
|---|---|---|
| `invertSubscriptions()` | `signals/topology.js:276` | Exported; only consumer was the removed "broadcasts-to" section of the Switchboard I/O tab. Still used by one test. Either delete + drop the test, or keep as eventual-future infra (document). |
| `roomLabel()` | `signals/roomLabel.js` | Unused in production since the I/O tab was removed. The SignalFeed now uses an inline `formatHop()`. Delete the file. |
| CLAUDE.md stale path | `CLAUDE.md:60` | Still references `src/components/room/resolveTerminals.js` — that file was moved to `src/signals/topology.js` and the old path deleted. Update the doc. |

### Component cohesion

- **App.jsx (677 lines)** — sized correctly. It owns app-wide state
  (model, processors, navigation, camera) by design. Effects are focused.
  Optional future extraction: `useNavigation()` hook for
  focusedId/paneId/systemView/camera-transitions — would drop App.jsx
  to ~550 lines and isolate the transition state machine. Not blocking.
- **Switchboard.jsx (363 lines)** — clean. Purely presentational; all
  state updates go out via props. Filter sub-components (TerminalDotRow,
  TypeChipRow, TagsInput) are well-encapsulated.
- **ProcessorPage.jsx (100 lines)** — clean. Uses `useSignalLog` hook
  cleanly; no direct bus subscriptions in component body.

### Remediation

1. Fix `wiring.js:23` to call `roomChannel(sourceRoomKey)`. 5 min. (P1)
2. Delete `signals/roomLabel.js`. Delete `invertSubscriptions` from
   `topology.js` and its test. Or keep and move an `@unused` marker.
   10 min. (P2)
3. Update `CLAUDE.md:60` to reflect `signals/topology.js`. 2 min. (P2)
4. Optional eslint rule forbidding literal `"room:"`/`"proc:"` channel
   strings outside `signals/bus.js`. Prevents the kind of drift that
   introduced the wiring.js violation. 15 min. (P3)

## 3 — WCAG 2.1 Level AA

### VPAT currency

`VPAT-2.5.md` is dated 2026-04-21 and **predates the entire
signal/processor UI**. None of the following are assessed in the VPAT:
Switchboard, ProcessorPage, ProcessorLibraryModal, SignalFeed,
CableTerminal, RoomShell (current form), TerminalDetail, Checkbox.
VPAT needs a refresh after the remediation below.

### AA-blocking (must fix for AA claim)

| # | Criterion | Location | Issue |
|---|---|---|---|
| B1 | 2.1.1 Keyboard | `Switchboard.jsx:277` rows | `<tr role="row">` has **no `tabIndex`, no `onKeyDown`**. Users cannot reach rows by keyboard, cannot open a processor, cannot toggle a dot without mouse. |
| B2 | 2.1.2 No keyboard trap | `ProcessorLibraryModal.jsx` | First-button focus on open ✓ and Escape handler ✓, but **Tab focus is not trapped**. Shift-tabbing past the first focusable escapes to the page behind. |
| B3 | 4.1.3 Status messages | `Switchboard`, `ProcessorPage` | No `role="status"` / `aria-live` announcements on processor add/remove, filter changes, or terminal-dot toggles. Screen-reader users are blind to state. (SignalFeed itself does have `role="log" aria-live="polite"` ✓.) |
| B4 | 2.5.5 Target size + 1.4.1 | Terminal dots in `Switchboard.jsx`, `Checkbox.jsx` | Dots are **14×14px**. Level AA minimum is **24×24px** (or equivalent separation). Below that unless we add explicit 8px separation + documentation. |
| B5 | 2.1.1 + semantics | `CableTerminal.jsx:101` | `<a href="#" role="link">` used as a button. Anchors without a real href are a longstanding AT quirk — should be `<button>`. |

### AA-significant (fix before the next VPAT refresh)

| Location | Issue | Criterion |
|---|---|---|
| `Switchboard.jsx` tags input (line ~127) | No `aria-label` / programmatic label | 2.4.6, 3.3.2 |
| `Switchboard.jsx` empty padding rows | Screen reader announces 10× "blank, blank, blank" per page | 1.3.1 |
| `Switchboard.jsx` grid | Missing `aria-rowcount`/`aria-colcount`; cells lack explicit `role="gridcell"` | 1.3.1 |
| `ProcessorLibraryModal.jsx:70` X button | `aria-label={tr('nav.esc')}` → renders as "esc" (keystroke) not "Close" | 2.4.4 |
| `RoomShell.jsx:58` back button | Same "esc" labeling issue | 2.4.4 |
| `SignalFeed.jsx:65` hops arrow | `color.borderLight` (#b5b5b5) is **2.1:1** on white — below AA | 1.4.3 |
| `SignalFeed.jsx:10–23` icons | `aria-hidden="true"` with no text alternative. Color-only type distinction. | 1.1.1, 1.4.1 |
| `Checkbox.jsx` unchecked state | Border `#8a8a8a` (3.5:1, at minimum) × `opacity: 0.35` = effectively ~1.9:1 perceived contrast. Below AA for UI boundaries. | 1.4.11 |
| `Switchboard` direction arrow inside dots | `aria-label` doesn't name the direction ("S3 (on)" vs. "S3 (on) — top wall"). Screen-reader user can't disambiguate the multi-red-dot case that arrows exist to solve visually. | 1.1.1 |
| `RoomShell.jsx` h1/h2 hierarchy | In a sub-page (system page), `<h1>` is the system verb and `<h2>` the unit name. In the document's outline, that's backwards from the expected page hierarchy. | 2.4.6 |
| `ProcessorPage.jsx:22–31` | Escape handler on `window` at capture phase — stacks if pages nest. Known pattern in this codebase (SystemPage has same), so the issue is structural. | 2.1.2 (edge case) |
| Switchboard, Modal, ProcessorPage | Various missing i18n keys (`systemPage.close`, `systemPage.back`, wall-direction names, time-format localization) | 3.1.2 |
| `TerminalDetail.jsx:32–47` | Connections shown as flex rows; no `<ul>`/`<li>` or definition-list semantics | 1.3.1 |

### AA-nice-to-have

StyleGuide page lacks landmarks and uses `<p>` for section headings
instead of `<h2>`. RoomShell content area could use `<main>`.

### Remediation

**P0 (AA blockers, ~5 hours):**
1. Add `tabIndex={0}` + `onKeyDown` (Enter/Space/ArrowDown/ArrowUp) to
   Switchboard rows. Mirror `ExplorerTree`'s keyboard pattern.
2. Implement focus trap in `ProcessorLibraryModal` — trap Tab and
   Shift-Tab within the dialog.
3. Add a `role="status" aria-live="polite"` live region for Switchboard
   state changes. Announce: "Processor X added", "Processor X removed",
   "Filter updated". Debounce 250ms to prevent spam.
4. Increase terminal-dot size from 14→20px in normal mode. Enforce 8px
   gap (already at 6px). Match in Checkbox tokens.
5. Change `CableTerminal.jsx:101` anchor to button.

**P1 (AA-significant, ~3 hours):**
6. Add `aria-label` to tags input. Hide empty rows with `aria-hidden`.
7. Fix mislabeled `nav.esc` buttons → `nav.back` or new `nav.close` key.
   Translate across 10 i18n files.
8. Darken `color.borderLight` usage in SignalFeed hops arrow to
   `color.muted` (or hide the arrow entirely and let spacing do the
   separation).
9. Add `aria-label` to SignalFeed icons (`"metric:"`, `"alert:"`, etc.)
   via visually-hidden spans.
10. Extend TerminalDot's `aria-label` to include the wall (`"S3 (on) —
    top wall"`) when the direction-arrow disambiguator is rendered.
11. Increase Checkbox unchecked-border contrast. Options: darker border
    (`color.muted` 4.5:1) or remove the opacity dim on the border (keep
    opacity only on fill).
12. Swap RoomShell `<h1>` verb / `<h2>` unit → `<h2>` verb / `<h3>`
    unit so the page-level title remains the document `<h1>`.
13. Use `<ul><li>` for TerminalDetail connections.

**P2 (quality):**
14. Refresh `VPAT-2.5.md`: add Switchboard/ProcessorPage/etc. to each
    criterion row. Note any remaining "Partially Supports" honestly.
15. Add axe-core test pass to the vitest suite for the Switchboard,
    ProcessorPage, and Modal in default + interacted states.
16. i18n: localize time format in SignalFeed; translate new keys.
